# Consignes de déroulement du PRI

Résumé des consignes données par l'encadrant le 9 novembre 2026, et la façon
dont ce dépôt y répond.

| Consigne | Réponse dans le projet |
| --- | --- |
| 1. Se former seul à un sujet non vu en TD | Planning de formation semaine par semaine, voir `planning.md` |
| 2. L'encadrant est un responsable hiérarchique de R&D, pas forcément expert : communiquer l'avancement clairement et préparer les réunions | Un compte-rendu préparé avant chaque réunion, voir `comptes_rendus/` |
| 3. Garder une trace structurée de la documentation : liens et commentaires sur l'utilité des ressources | `documentation/sources/`, un fichier par thème |
| 4. Documenter au fur et à mesure : questions, réponses partielles, échanges en réunion | `documentation/journal_de_reflexion.md` et la partie « après la réunion » de chaque compte-rendu |
| 5. Dépôt GitHub public, formats texte, commentaires de commit et branches soignés | Dépôt public, `documentation/conventions_git.md` |
| 6. Le PRI est une occasion d'apprendre ; le rapport doit être très pédagogique pour des lecteurs non experts | Rapport Sphinx dans `rapport/`, écrit au fil des semaines |
| 7. Ébauche de planning inversé vers un rendu début janvier, avec priorisation nécessaire, intéressante, optionnelle | `planning.md` |
